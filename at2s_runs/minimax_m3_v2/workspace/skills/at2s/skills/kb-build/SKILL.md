# kb-build — 从证据生成知识库

用于从用户指定的资料和只读数据库构建当前 at2s 副本自己的 `.knowledge/`。不读取题目答案、评测文件、历史预测或其它模型知识库。

## 产出

- `.knowledge/architecture/index.md`：轻量选表索引。
- `.knowledge/architecture/<表名>.md`：表描述、粒度、日期、字段和可信来源。
- `.knowledge/architecture/correlation.md`：Join 矩阵、关系证据和跨表注意事项。
- 缺失时创建 `.knowledge/conventions/` 与 `.knowledge/troubleshooting/` 目录；不凭空生成业务约定。

## 可信来源

字段、关系和码值逐条标记以下来源之一：

| 来源 | 可直接用于 SQL | 要求 |
|---|:---:|---|
| `用户确认` | 是 | 用户明确说明 |
| `资料明确` | 是 | 用户指定资料直接给出 |
| `数据库验证` | 是 | 只读查询得到可复核证据 |
| `数据推测` | 否 | 仅由字段名、少量样本或惯例推断 |

`数据推测` 进入“待确认”，不得写成确定码值、确定业务公式或硬约束。

## 流程

### 0. 边界与编码预检

1. 确认目标表、资料路径、知识库输出路径和只读访问方式均属于用户给定范围。
2. 通过 `db-access` 检查 `client_encoding`，并读取至少一组已知包含中文的 `code/describe` 或名称字段。
3. 若输出含 `�`、连续问号、明显 mojibake 或中文不可读，立即停止本批知识构建并报告编码问题；**禁止猜码值映射**，不得根据码值顺序、长度或“最高等级”等惯例补写含义。
4. 预检通过后才创建或写入稳定知识文件。

### 1. 收集结构和样本

- 查询字段名、数据库类型和约束；每表抽样不超过 100 行。
- 码值字段读取不超过 100 个去重值；存在码表时查询 `码域 + code + 可读 describe`，不要只取 code。
- 记录实际日期最小值、最大值、粒度候选和唯一性验证结果。
- 抽不到数据、文件匹配不唯一或关键查询失败时停止，不凭表名补写。

### 2. 生成每表知识

每个 `<表名>.md` 至少包含：

1. `## 表描述`：业务用途、每行粒度、主键候选、日期范围。
2. `## 字段`：字段名、类型、含义、示例/码值、来源。
3. `## 数据特征`：空值、唯一性、可汇总性和码值域。
4. `## 待确认`：所有 `数据推测` 及其缺失证据。

精确码值映射只有在中文可读且 `code_type_id/code/describe` 同时得到验证时才标 `数据库验证`。不可读文本不能进入映射表。

已有文件默认跳过；用户明确要求重建时，先列出覆盖范围并按该范围重写，不混合旧推测。

### 3. 统一分析关系

批量构建时先完成全部表文件，再统一生成 `correlation.md`。

- Join 候选同时检查字段含义、值形态和匹配覆盖率；字段同名本身不足以确认关系。
- 未经用户、资料或数据库覆盖率验证的关系标 `推测`；空白代表未分析，`∅` 代表已有证据证明无直接关系。
- 注意事项只记录会改变 SQL 写法的规则，如粒度放大、日期无交集、币种/账户维度和不可直接汇总字段。
- 一条注意事项只表达一个可执行结论，并标明来源。

### 4. 生成路由索引

`architecture/index.md` 每表一行，格式为：

| 表名 | 一行粒度 | 主题关键词 | 日期字段/范围 | 主标识 | 常见关联 |
|---|---|---|---|---|---|

索引只做路由，不复制完整字段表、码值或长篇注意事项。`text2sql` 先读索引，再按需打开表文件。

### 5. 完整性检查

- 每个目标表均有非空表文件并出现在 `index.md`。
- `correlation.md` 包含完整矩阵、关系明细和注意事项。
- 所有精确码值均有前三类来源，所有推测均出现在“待确认”。
- 搜索替换字符 `�`、明显乱码、答案路径、题号和 SQL 答案；命中则停止并报告。

## 常见错误

| 错误 | 处理 |
|---|---|
| 中文不可读仍按编号猜含义 | 停止构建，先修编码 |
| 抽到一个样本就确认字段业务含义 | 标为 `数据推测` |
| 把字段同名当作已确认 Join | 验证值域与覆盖率 |
| 把完整字段表复制到 index | 索引只留路由信息 |
| 从题目或 Gold 反推知识 | 禁止读取，不作为构建证据 |

## 幂等

- 同一证据输入重复构建应得到等价内容。
- 不静默覆盖已有表文件。
- 关系按规范化表对更新，不重复追加。
