# at2s — Agentic Text2SQL

## 约定

- **SQL 方言统一用 PostgreSQL**，包括最终产出的答案 SQL 与各子流程内部的临时查询。

## 初始化路径

### 首次使用（强制）

**首次使用本技能时，无论用户问什么，都先跑一次 kb-check 完整性检查。**
首次使用的判据：记忆里没有本技能的使用经历。据此判断为首次后，先体检再据结果决定走标准路径还是直接应答，并记录一次使用经历，之后不再强制。

### 标准路径（用户问"怎么用"时）

先**静默调用 kb-check** 体检。若缺东西，按下列顺序告诉用户，并**由用户监督逐步进行**，一步一确认：

1. 建 `.knowledge/` 目录结构（kb-check 补建）
2. 配置查表方式（db-access）
3. 构建知识库（kb-build）
4. 可选：配置自动消化（kb-refine 的 `config.md`）
5. 以上就绪即可开始问数（text2sql）

若 kb-check 显示都齐了，直接告诉用户可以开始问数。

### 快速路径（用户说"想快速开始用"时）

开启快速初始化：向用户一次性索取足够信息——**查表方式** + **一个表的信息文件或目录**，
拿到后**一步到位**跑完所需初始化（建目录 → 配 db-access → kb-build 建库），中途不逐步等确认。
**快速路径不配置、也不触发自动消化 troubleshooting。**

## 子流程

子流程文档在本技能目录的 `skills/` 下，按调用时机分派。

**知识库就绪后，`text2sql` 是日常主路径**：用户抛出一个问数需求而未特别说明时，默认走它；其余四个都是围绕知识库的准备与维护工作。

### kb-check — 知识库完整度检查

文档：`skills/kb-check/SKILL.md`

调用时机：

1. 用户明确要求检查知识库完整度时。
2. 用 text2sql（5 号）生成 SQL 之前，**总是先调用一次**查看完整度。

跳过规则：用户明确表示不必检查、直接出 SQL 之类的意思时，跳过第 2 条。跳过后在交付里注明本次未做知识库体检。

### db-access — 数据库访问

文档：`skills/db-access/SKILL.md`

调用时机：

1. 用户单独提出要配置连接数据库的方式时。**先确认是追加还是覆盖** —— 环境里可能同时存在多种调数据库的方式，默认按追加处理，不要擅自覆盖已有配置。
2. kb-check 报告查表方式未就绪、并给出配置建议后，跟从该建议配置 2 号。

### kb-build — 生成知识库

文档：`skills/kb-build/SKILL.md`

调用时机：

1. 用户要求为某张表或某批表建知识库时（可指定单表、批量文件，或整个数据目录）。
2. kb-check 报出"待补充"或"潜在可添加"并给出建议后，跟从该建议对相应表调用。

生成内容写入 `.knowledge/architecture/`：每表一个 `<表名>.md`，表间关系汇总到 `correlation.md`。已有文件默认跳过，不静默覆盖。

### kb-modify — 修改知识库

文档：`skills/kb-modify/SKILL.md`

调用时机：

1. 用户要解答 kb-build 生成时留下的困惑，或复核知识库里的推测内容。
2. 用户手动指出知识库有错，要改某些表的知识。

未指明属于哪种时先问用户。沟通后先与用户约定修改计划，确认后才改；计划外的内容不动。

### text2sql — 生成 SQL

文档：`skills/text2sql/SKILL.md`

**知识库就绪后最常用的子流程。**

调用时机：

1. 用户给出一段 text，要求据此查数据或生成 SQL——包括未明说“生成 SQL”但实质是问数的请求。
2. 用户要求复核已生成的 SQL。

两条硬规则：

- **默认不得中途追问**。仅当用户明确表示可以提问时才允许；否则遇模糊自行拍最合理解释，照常产出，但必须在交付里逐条声明假设。
- 本流程**只产出 SQL，不执行查询**；db-access 仅用于抽样取证。

收尾必须把本次的模糊点与用户解答（如有）写入 `.knowledge/troubleshooting/`；用户反馈 SQL 错了也记录。

### kb-refine — 完善知识库

文档：`skills/kb-refine/SKILL.md`

调用时机：

1. text2sql 在 troubleshooting 里积了疑问或错误后，用户要求据此回头完善知识库。
2. 用户指出某次出错源于缩写、黑话、别名，要沉淀进知识库。

与 kb-modify 的分工：kb-modify 处理知识库内部的未确认内容与用户当面指错；kb-refine 消化 text2sql 用过之后留下的 troubleshooting 记录。黑话/别名写入 `conventions/aliases.md` 与对应 `<表名>.md` 两处（有意冗余）。
