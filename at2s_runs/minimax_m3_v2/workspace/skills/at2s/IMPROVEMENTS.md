# AT2S Skill 改进说明

## 背景

一次批量评测的 EX 为 34.02%（33/97），相比此前结果明显回退。逐题对比显示，主要问题不是知识库缺失，而是 SQL 生成阶段出现了系统性的结果形状、数值精度和隐式筛选错误。

本轮修改聚焦可泛化的 Text2SQL 行为，不写入题号对应答案、Gold SQL 或单题特例，也不修改 `.knowledge` 内容。

## 核心改进

### 1. 最小结果形状

- “客户名单”“哪些客户”“前 N 客户”默认使用 `pty_id` 表达客户；只有题目明确要求姓名时才增加 `name`。
- “各营业部/分公司”默认返回对应机构名称和题目要求的度量；只有明确要求编号时才增加机构 ID。
- “各产品分类”默认返回分类名称和题目要求的度量；只有明确要求代码时才增加分类 ID。
- 连接键、辅助分组键、中间排名和解释字段保留在 CTE 或子查询中，不自动暴露到最终结果。

### 2. 数值精度边界

- `SUM`、原始金额和金额排名默认保持数据库精度，不再统一套用 `ROUND(..., 2)`。
- 平均年龄仍按已确认约定保留 1 位小数。
- “占比/占全部的比例”仍返回 0–100 百分数并保留 2 位小数。
- 其它数值只有在题目明确要求精度，或知识库存在已确认输出约定时才格式化。

### 3. 筛选条件可追溯

- 日期、账户 `sys_source`、币种、产品和客户范围必须来自题目文字，或题目中显式业务术语的已确认定义。
- 题目未给日期时，不因表中存在 `data_dt` 或当前只有一个快照而虚构日期过滤。
- 题目明确“普通账户”时才按其定义使用 `sys_source='nm'`；“全体客户”不隐含普通账户过滤。
- 知识库说明某个字段或码值可用，不代表所有查询都必须输出该字段或使用对应过滤。

### 4. 字段归属检查

独立审计逐个核对 `alias.column` 是否属于别名对应的表，重点避免把客户画像字段、产品分类字段或机构字段错误引用到事实表别名上。

### 5. 两遍生成与独立审计

批量模式改为：

1. 第一遍只分析题目，冻结意图卡与输出契约。
2. 第二遍按冻结契约生成 SQL。
3. 全部草稿完成后重新根据原题进行独立审计。

批量脚本只能保存已经复核的 SQL，不得通过通用模板统一增加展示列、`ROUND` 或过滤条件。审计不能用草稿 SQL 反向证明其输出结构正确。

### 6. 知识库边界

- `.knowledge` 只保存可跨题复用、具有证据的表结构、字段含义、码值和业务关系。
- 评测错误、题号、标准答案和单题 SQL 不晋升为稳定知识。
- 批量生成期间固定知识库快照，不运行 `kb-refine`，避免同一批次前后知识状态不一致。

## 主要文件

- `SKILL.md`：AT2S 总体原则、批量流程和交付自检。
- `skills/text2sql/SKILL.md`：输出契约、精度、筛选、字段归属与独立审计规则。
- `skills/kb-build/SKILL.md`：知识库从零构建和证据标记规则。
- `skills/kb-check/SKILL.md`：知识库完整性与批量快照检查。
- `skills/kb-refine/SKILL.md`：稳定知识晋升与评测泄漏门禁。
- `skills/db-access/`：PostgreSQL 只读访问边界和封装脚本。

## 验证结果

- AT2S v2 静态验证通过。
- Skill 结构验证通过。
- 答案路径、Gold SQL、评测文件和题号特例泄漏扫描为 0。
- 修改时现有 10 个 `.knowledge` 文件与生成快照哈希一致。
- 历史 predictions 和 evaluation 未被覆盖。

## 后续评测建议

先保持同一份 `.knowledge` 不变，只使用改进后的 Skill 重新生成 SQL。这样可以单独衡量 Skill 行为修改的效果。完成该组评测后，再重新生成知识库进行第二组实验，避免同时改变 Skill 和知识库而无法判断提升来源。

上述验证证明文件结构和规则完整，不代表模型准确率已经提升；最终效果仍需通过新的 97 题评测确认。
