# text2sql — 生成或复核 SQL

at2s 的日常子流程。核心目标是生成与问题要求一致的结果集，而不是补充一个“看起来更丰富”的报表。

## 产出

- PostgreSQL；一个问题一条 `SELECT` 或 `WITH ... SELECT`。
- 单题交付 SQL、口径和假设；批量交付按上层 Prompt 指定的纯 SQL 文件与说明文件。
- 只抽样取证，不执行答案 SQL。

## 模式预检

- 单题：首次使用或知识库变化后运行 `kb-check`；状态未变则复用本会话结果。
- 批量：整个题目文件只体检一次并固定知识库快照。批次内不运行 `kb-refine`，也不修改稳定知识。

## 流程

### 1. 建立意图卡和输出契约卡

写 SQL 前先在内部确定：

| 卡片 | 必填项 |
|---|---|
| 意图卡 | 主体、目标粒度、筛选条件、时间范围、度量公式 |
| 输出契约卡 | 返回列名称/含义、列顺序、每行代表什么、单位/精度、排序与 Top N |

最终 `SELECT` **只输出契约卡中的列，并保持同一顺序**。分母、连接键、代码、分组键或解释标签若不在契约卡中，只能留在 CTE/子查询内。不得添加“方便理解”的辅助列。

先用下列最小结果形状消解常见省略；题目明确列出展示字段时，以题目为准：

| 题目表达 | 最小结果形状 |
|---|---|
| 客户名单、前 N 客户、哪些客户 | 客户标识 `pty_id`；只有明确要求姓名时才增加 `name` |
| 各营业部、各分公司分布 | 对应机构名称 + 题目要求的度量；只有明确要求编号时才增加机构 ID |
| 各产品分类 | 对应分类名称 + 题目要求的度量；只有明确要求代码时才增加分类 ID |
| 客户及其某项指标 | `pty_id` + 该指标；“客户”本身不自动展开成姓名、机构或画像字段 |

“名单”描述实体集合，不等于要求返回该实体所有可读属性。若问题只给出实体类型而未指定展示属性，使用稳定标识表达实体。

通用输出约定，若 `.knowledge/conventions/` 有用户确认规则则以后者为准：

- “占比”“占全部的比例”返回 0–100 的百分数，保留 2 位小数；“A/B 比值”才返回原始比值。
- 平均年龄使用 `round(avg(...), 1)`，保留 1 位小数。
- `SUM`、原始金额及金额排名默认保持数据库精度，不得自动 `ROUND`；金额平均值、比例或其它数值也只有题目明确要求精度，或 `.knowledge/conventions/` 存在已确认规则时才格式化。
- 题目未要求时，不主动增加总数、代码列、中文标签、姓名、机构号或中间排名。
- 排序列可以不出现在结果中；Top N 有并列规则时按题意选择 `rank`/`dense_rank`，否则用稳定次级键限定边界。

### 2. 术语归一与按需选表

1. 若存在 `.knowledge/conventions/aliases.md`，先读取相关别名。
2. 优先读取 `.knowledge/architecture/index.md`，按关键词、粒度和日期筛选候选表。
3. `index.md` 不存在时，只查看 `architecture/` 顶层文件名和各文件的“表描述”摘要；不要通读全部表文件。
4. 只打开候选表的 `<表名>.md`。仅从 `correlation.md` 读取候选表对应的关系与注意事项。

候选表以最小充分集合为准。新增一张表必须对应一个无法由现有候选表提供的字段、筛选或度量。

### 3. 证据与码值

可信度顺序：`用户确认` > `数据库验证` > `资料明确` > `数据推测`。

- 精确码值、中文描述、日期覆盖或连接键只有达到前三类可信度时才能直接写死。
- 若码值仅为推测，优先关联码表后按用户给出的中文语义过滤；不得根据编号大小、字段顺序或“通常如此”猜码值。
- 抽样只用于当前问题仍未解决的具体值、字段形态或日期边界，不对每张候选表重复抽样。
- 抽样结果出现 `�`、明显乱码或不可读描述时，不使用该文本建立映射；改用可验证查询或把风险写入假设。
- 知识库说明某字段或码值的含义，只证明它可用于表达题意，不代表所有查询都必须输出该字段或套用对应过滤。

### 4. 按目标粒度规划

先写出“每个 CTE 一行代表什么”，再生成 SQL：

- 题目明确日期、期间或“期末/当日”时，对参与计算的时间表使用对应 `data_dt`；题目未指定日期时，不得因为表含日期字段或当前只有一个快照就虚构日期过滤。
- 日期、账户 `sys_source`、币种和产品范围只来自题目明确条件，或题目所用业务术语在稳定知识中的已确认定义。例如题目明确“普通账户”时才能据其定义过滤 `nm`；“全体客户”不隐含普通账户过滤。
- 一对多事实表先聚合到目标粒度再关联，避免金额和人数放大。
- 客户数根据目标粒度选择 `count(*)` 或 `count(distinct pty_id)`，不机械地全部去重。
- `AVG` 前先确认输入是否已是一客一行；跨表画像平均值先聚合事实表，再与客户表关联。
- 比例先独立定义分子、分母和单位；最终只暴露输出契约要求的比例列。
- 多日期、清仓、迁移、首次发生等问题先构造各日期/月份集合，再做集合或窗口运算。

### 5. 生成并独立审计

生成后执行第二遍独立审计：重新只看原问题和已冻结输出契约，再与 SQL 对照；不得从草稿已有列、过滤或格式反推题意。逐项核对：

1. **结果形状**：最终列数、含义、顺序和输出契约卡完全一致。
2. **筛选可追溯**：每个日期、账户、币种、产品或客户范围都能指回题目文字或已确认的显式术语定义；删除其余隐式过滤。
3. **字段归属**：逐个检查 `alias.column` 确实属于该别名对应的表，尤其检查从画像表引入事实表没有的分类字段。
4. **粒度安全**：每个 JOIN 两侧粒度已知，不会重复计数或重复求和。
5. **计算正确**：空值、分母为零、百分数/比值、平均值和排名规则已处理；合计和原始金额未被无依据降精度。
6. **最小化**：删除不服务于题意的表、列、格式化和排序。

若审计发现问题，修改 SQL 后重新检查；不能仅在说明中提示而保留已知错误。

## 模糊处理

- 允许追问：一次列全关键模糊点，得到答复后生成。
- 默认不允许追问：采用最有证据的解释并声明假设。
- 不可读码值不是普通业务歧义：不得猜具体代码。能通过已验证的码表关系按语义过滤则降级生成；否则停止该题或批次并报告知识库未就绪，不得把占位符写入 `predictions.txt`，也不能伪装成已确认映射。

## 记录规则

- 单题交互：真正未解决的业务歧义写入 `.knowledge/troubleshooting/questions.md`；用户反馈的错误写入 `errors.md`。
- 批量评测：只写上层指定的 `generation_notes.md`，不逐题改 `.knowledge`。批次结束后只有用户明确要求，才把可复用问题汇总进 troubleshooting。
- 记录不得包含标准答案 SQL，也不得把某个题号的特例描述成通用规则。

## 常见错误

| 错误 | 修正 |
|---|---|
| 为解释代码额外输出名称列 | 名称只在契约要求时输出 |
| “客户名单”自动输出姓名 | 未明确要求姓名时只输出 `pty_id` |
| 金额合计统一 `ROUND(..., 2)` | 保持数据库精度，只有明确精度规则才格式化 |
| 因表中存在日期或账户字段就自动过滤 | 只保留题目或已确认显式术语要求的条件 |
| 在事实表别名上引用画像字段 | 逐列核对字段归属，从正确表引用 |
| 比例题同时输出分母 | 分母留在 CTE，最终只输出题目要求列 |
| `AVG` 直接跨一对多 JOIN | 先聚合到目标实体，再求平均 |
| 只有一个快照就省略日期 | 仍显式过滤，固定查询语义 |
| 乱码时猜码值 | 改用码表语义过滤或标为未确认 |
