# at2s — Agentic Text2SQL

## 核心原则

目标是让 SQL 的**结果集语义和形状**与问题一致，而不只是让 SQL 可以执行。

- 方言统一为 PostgreSQL。
- 一个问题输出一条 SQL，可包含多个 CTE；不执行答案 SQL，不编造结果。
- 只加载本技能目录自己的 `.knowledge/`；不读取答案、评测结果、历史 predictions 或其它模型知识库。
- 已确认、资料明确或数据库验证的事实可以直接使用；`数据推测` 只能作为候选，不能把不可读码值或业务含义猜成确定过滤条件。
- 输出列、顺序、粒度、单位和精度是正确性的一部分。辅助计算放在 CTE 中，不自动暴露为结果列。

## 文件系统边界

- 本技能目录是包含本文件的 `at2s/`，所有相对路径只解析到这里。
- 技能目录外仅访问用户明确给出的路径，以及 `skills/db-access/access.md` 登记的资源。
- 不枚举父目录、兄弟模型目录或其它工作区；临时文件只放当前模型工作区的 `generated/.tmp/`。
- `.knowledge/` 的业务内容由模型通过 `kb-build` 生成。本技能文件不得预填题目答案或复制其它模型知识。

## 工作模式

### 单题模式

首次使用或知识库状态变化后运行一次 `kb-check`，随后调用 `text2sql`。同一会话内知识库未变化时复用体检结果。

### 批量模式

一个题目文件视为一个批次：

1. 批次开始运行一次 `kb-check`，固定本批知识库快照。
2. 第一遍只根据题目冻结每题的意图卡与输出契约，不生成最终 SQL；每题只加载相关表知识和关联规则。
3. 第二遍按已冻结契约生成 SQL，不得让批量脚本、通用模板或字段可用性扩展输出列、格式或筛选条件。
4. 全部 SQL 完成后独立复核题目、契约和最终 SQL；复核时重新从题目判断结果形状和显式筛选，不以草稿 SQL 自证正确。
5. 批次中不运行 `kb-refine`，不修改 `architecture/`、`conventions/` 或 `correlation.md`。
6. 模糊点集中写入批次说明；用户明确要求时，批次结束后再写 troubleshooting。

## 子流程路由

| 请求 | 子流程 | 文档 |
|---|---|---|
| 检查知识库、首次使用、批次预检 | `kb-check` | `skills/kb-check/SKILL.md` |
| 配置或使用只读数据访问 | `db-access` | `skills/db-access/SKILL.md` |
| 从数据资料和数据库生成 `.knowledge` | `kb-build` | `skills/kb-build/SKILL.md` |
| 生成或复核 SQL | `text2sql` | `skills/text2sql/SKILL.md` |
| 用户确认后修正已有知识 | `kb-modify` | `skills/kb-modify/SKILL.md` |
| 消化 troubleshooting 并晋升通用知识 | `kb-refine` | `skills/kb-refine/SKILL.md` |

知识库缺失时先报告缺口；用户明确要求从零构建时直接走 `kb-build`。默认不追问的批量评测仍需产出 SQL，但必须在说明文件中记录未确认假设。

## 快速自检

交付前确认：

- 只使用允许的知识和数据源。
- SQL 返回列与问题要求一一对应，没有额外展示列。
- 日期、账户、币种和产品过滤均能追溯到题目或已确认的显式术语定义，没有因为字段存在而自动增加。
- 快照日期、目标粒度、关联放大、字段归属、空值和计算单位均已检查。
- 不把乱码、题号、单题答案或未经验证的推测沉淀成稳定知识。
