# kb-check — 知识库预检

用于检查当前 at2s 副本的知识库是否可供问数使用。检查阶段只读；补结构必须先获得用户同意，且不生成业务知识。

## 执行频率

- 单题：首次使用或知识库变化后运行；同一会话内状态未变可复用。
- 批量：一个题目文件在批次开始只运行一次。记录知识文件清单及 SHA-256；批次内指纹不变则不得逐题重复体检。
- 用户明确要求重新检查时立即运行。

## 检查项

| 项目 | 完整条件 |
|---|---|
| 目录 | `.knowledge/architecture`、`conventions`、`troubleshooting` 存在 |
| 数据访问 | `skills/db-access/access.md` 至少有一个非占位条目 |
| 表知识 | 每个目标表有 `<表名>.md`，包含“表描述”“字段”“待确认” |
| 路由索引 | `architecture/index.md` 存在且覆盖全部表知识文件 |
| 表关系 | `architecture/correlation.md` 有矩阵、关系明细和注意事项 |
| 可信度 | 精确码值没有仅标 `数据推测`；乱码没有进入稳定知识 |
| 自动消化 | 只报告 `kb-refine/config.md` 状态，不把未配置视为缺失 |

没有用户明确提供权威表清单时，不输出完成度百分比。

## 流程

1. 只扫描当前技能目录的 `.knowledge/`，不搜索其它工作区。
2. 列出表文件集合 `S_self`、索引集合 `S_index`、矩阵中有关系的集合 `S_rel` 和已确认孤立集合 `S_iso`。
3. 报告：
   - 完善：同时属于 `S_self` 与 `S_index`，且属于 `S_rel` 或 `S_iso`。
   - 待补充：缺表描述、索引或关系证据。
   - 风险：精确映射仍为推测、出现乱码、推测被写成硬约束。
   - 潜在可添加：仅来自用户明确给出的线索源。
4. 需要补目录或占位骨架时先取得用户同意；内容交给 `kb-build`。

## 报告格式

```markdown
**结构**：<目录和核心文件>
**访问**：<已配置/未配置>
**知识快照**：<文件数与 SHA-256 摘要>
**表**：<完善 / 孤立 / 待补充 / 潜在可添加>
**可信度风险**：<码值、乱码、推测硬编码；无则写“无”>
**建议动作**：<按优先级列出>
```

## 补全边界

- 只创建缺失目录或带 `<!-- kb-check:placeholder -->` 的空骨架。
- 不覆盖、删除或自动修正已有知识。
- `.knowledge` 不存在且用户要求从零构建时，直接报告未就绪并路由到 `kb-build`，不从其它模型复制。
