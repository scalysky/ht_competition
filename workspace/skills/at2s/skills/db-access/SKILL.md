# db-access — 数据库访问

at2s 的子流程，不对外暴露。**调用时机**：其它子流程需要看真实数据（抽样、字段、取值分布）时；用户要求配置或更换数据库访问方式时。

## 状态判定

`access.md` 以**条目**形式记录查表方式，可以有多条（环境里可能同时存在多种通道）。

- **文件不存在，或没有任何一条非占位条目** → 未配置。进入下面的"沟通配置"，**不要自行猜测连接方式，不要试探性连库**。
- **至少有一条非占位条目** → 已配置。按"标准动作"执行。

## 沟通配置

一次性问全，不要挤牙膏：

1. 数据源形态：真实数据库 / 本地 CSV / 导出的样例数据
2. 若为数据库：类型与版本、库名、schema
3. 交互通道：命令行客户端 / 编程语言驱动 / 现成脚本 / MCP 工具 / 只能由用户代跑再粘贴结果
4. 凭据获取方式：环境变量名 / 配置文件路径 / 每次由用户临时提供
5. 只读边界：允许哪些语句、单次返回行数上限

用户答完，把结论作为**一个条目**写入本目录的 `access.md`（**只记交互方式，不记凭据**），每条给一个可读的名字并标明尝试优先级；需要脚本则放本目录 `scripts/` 下。

已有条目时，先确认是追加新条目还是覆盖某条，默认追加。

## 标准动作

已配置后对外提供三件事，供 3 号等子流程调用：

- **抽样**：取某表前 N 行
- **结构**：列出某表字段名与类型
- **取值分布**：看某字段的去重取值，用于码值类字段

### 多方式的尝试顺序

存在多条方式时按优先级**逐一尝试**：

1. 某条失败不算失败，记下失败原因，换下一条继续。
2. 任一条成功即视为成功，在结果里注明实际用的是哪条。
3. **只有全部条目都失败才报错**，报错时汇总每条的失败原因，便于定位是环境问题还是配置过期。
4. 不要因为第一条失败就判定未配置，也不要因此回到"沟通配置"。

## 安全约束

- 只读。不执行写入、DDL、删除。
- 凭据不写入任何文件、不写入记忆、不回显。
- 本目录下的凭据文件与脚本产物需 gitignore。
- 每次查询带行数上限，不做全表拉取。
