# dim_branch

## 表描述

- 表的业务含义：营业部/机构维度表，描述证券营业部及其上级机构（分公司）的层级关系，用于客户归属机构的名称补全与层级聚合。
- 数据粒度：一行 = 一个机构（`org_id`）在某一个数据日期（`data_dt`）的机构信息。
- 每行代表什么：一个营业部或分公司的机构号、机构名称，及其直属上级机构号和名称。
- 可能的主键或唯一键：`(data_dt, org_id)`。抽样中 `data_dt` 唯一值为 `20260531`，`org_id` 唯一（312 个机构）。
- 日期字段和时间范围：`data_dt`（字符型 8 位，YYYYMMDD），库内仅 `20260531` 一个日期（312 行）。
- 适合回答的业务问题：按营业部、分公司统计客户；机构名称补全；机构层级（营业部→分公司→财富管理部）聚合；客户归属营业部的上级分公司归属。
- 使用时需要注意的限制：`org_name`/`up_org_name` 已脱敏（名称中间用 `******` 遮掩，如 `包头******营业部`）；`up_org_id` 存在多级：多数营业部上级为分公司（如 XX00000112 北京分公司），分公司上级为 XX000001（财富管理部）；部分机构本身是分公司（org_id=XX00000080 南京分公司等）。不能把 org_name 当作完整名称直接展示。

## 字段

| 字段名 | 数据类型 | 字段说明 | 示例或码值 | 来源 |
|---|---|---|---|---|
| data_dt | character varying(8) | 数据日期，YYYYMMDD | 20260531 | 用户提供 |
| org_id | character varying(50) | 机构号（营业部/分公司标识），关联 ads_cust_info_d.org_id | XX00000054 | 用户提供 |
| org_name | character varying(100) | 机构名称（已脱敏，含 `******`） | 包头******营业部 | 用户提供 |
| up_org_id | character varying(50) | 直属上级机构号 | XX00000112 | 数据推测 |
| up_org_name | character varying(100) | 直属上级机构名称（已脱敏） | 北京分公司 | 数据推测 |

## 数据特征

- 抽样中发现的主要取值特征：`org_id` 形如 `XX`+8位数字（XX00000001 等）；`org_name` 多为 `城市名******营业部`，分公司为 `省/城市分公司`，上级顶点为 `财富管理部`（up_org_id=XX000001）。
- 空值情况：全部字段非空（DDL 均为 NOT NULL）。
- 码值字段：无标准码值字段；`up_org_id` 为机构层级编码。
- 金额和数量字段：无。
- 日期字段：`data_dt` 库内仅 20260531。
- 客户、产品、机构等标识字段：`org_id` 机构主标识；`up_org_id` 上级机构标识，可用于层级聚合。
- 可能影响聚合或关联的粒度问题：一行一机构一日期；机构存在多级（营业部→分公司→XX000001 财富管理部），按 up_org 聚合时注意部分机构本身是分公司（其上级直接是 XX000001）。ads_cust_info_d 的 org_id 全部能在本表找到（抽样验证 0 缺失），但本表有 312 个机构而 ads 只涉及 28 个不同 org_id。

## 待确认

- `XX000001`（财富管理部）是否为最高层级总节点，层级数量及完整树状结构需人工确认。
- 各 `org_id` 属于营业部还是分公司需结合名称与 up_org 关系人工确认。
- `org_name` 脱敏规则（`******` 固定 6 个星号）需确认，无法用于精确匹配。
- 表中仅一个 data_dt，是否另有历史版本未知。
