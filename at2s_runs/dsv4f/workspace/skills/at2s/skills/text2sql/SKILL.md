# text2sql — 生成 SQL

at2s 的子流程，不对外暴露。**调用时机**：用户给出一段 text，要求据此生成 SQL 查询；或要求复核已生成的 SQL。

## 产出契约

- 方言 PostgreSQL（见主 SKILL.md 的约定）。
- **只产出 SQL 文本与口径说明，不执行查询、不编造结果。**
- 一个问题对应一条 SQL（可含多个 CTE），不拆成多条让用户自己拼。
- 2 号（db-access）在本流程中**仅用于抽样看数据**，不用来跑答案 SQL。

## 流程

### 0 知识库体检

先调 kb-check（主 SKILL.md 已规定）。用户明确表示不必检查时跳过，并在交付里注明未体检。

### 1 分析 text

拆出五项：主体粒度、筛选条件、时间范围、度量、输出列。逐项对照，缺项进入「模糊处理」。

读 `.knowledge/conventions/`（如 `aliases.md`）：把 text 里的缩写、黑话、别名换成库内准确值或字段名。**在选表之前做**，否则黑话没翻译会漏选表或误选表。conventions 里没有的口语，进入「模糊处理」。

### 2 列出可能用到的表

通读 `.knowledge/architecture/` 下**所有** `<表名>.md`，据表描述与字段含义筛出候选表，并说明每张表因何入选。
宁可多列一张再排除，不要漏。

### 3 查看关系与注意事项

读 `.knowledge/architecture/correlation.md`，三部分都要看：

**join 矩阵** —— 为候选表两两确定 join 字段：

- 关系状态为 `推测` 的，可用但需在交付里提示。
- 单元格为 `∅` 的表不可 join，若必须同时用到，考虑笛卡尔积或改思路。
- 留空的表示关系未分析，**不要凭空造 join 键**。

**关系明细** —— 取具体的关联条件与附加限定。

**注意事项** —— **每次生成 SQL 前通读全部条目**，挑出涉及候选表的那几条，在第 5 步逐条遵循。
这里装的是本数据集特有的坑（字段类型、码值关联方式、可汇总性、时间覆盖等），不读就会写出语法对、结果错的 SQL。

### 4 抽样取证

用 2 号对候选表抽样，验证：筛选值是否真实存在（尤其中文取值与码值）、字段取值形态、时间边界是否落在该表 `data_dt` 覆盖范围内。

**抽样是必要步骤**：知识库说得再全，筛选条件里的具体取值仍需实测确认存在，否则生成的 SQL 语法正确但查不出东西。

### 5 生成 SQL

信息充分后再写。约束：

- **逐条遵循第 3 步读到的注意事项**。数据集特有的写法规则全在那里，本文不重复。
- 口径优先级：知识库里标为 `用户确认` 的最优，其次 `表描述`，最后 `数据推测`。
- 表名、字段名必须来自知识库或抽样所见，**不得臆造**。
- 多段筛选拆成语义化 CTE；输出列取有业务含义的别名。

### 6 记录到 troubleshooting

见下方「记录规则」。**无论是否追问过都要走这一步**。

## 模糊处理与追问权限

**默认不允许追问。** 只有用户在本轮或此前明确表示可以中途提问时才允许。

| 情形 | 处置 |
|---|---|
| 允许追问 | 一次性列全所有模糊点，取得答复后再生成 |
| **不允许追问（默认）** | **自行选择最合理解释**，照常产出 SQL，但必须：① 在交付的「假设」里逐条显式声明；② 把每个模糊点记入 troubleshooting |

不允许追问时**不得因模糊而拒绝产出**，也不得把假设藏在 SQL 里不说。

## 交付格式

```markdown
**候选表**：<入选的表及理由，一行一张>

**口径**：<时间范围 / 主体粒度 / 度量定义>

**假设**：<自行拍定的解释，逐条；无则写"无">

```sql
<SQL>
```

**提示**：<用到了状态为 `推测` 的关系、跳过体检、未确认口径等风险；无则省略>
```

## 记录规则

写入 `.knowledge/troubleshooting/`：

| 文件 | 内容 |
|---|---|
| `questions.md` | 本次的模糊点。每条记：原始 text、模糊在哪、处置（`用户解答：…` 或 `自行假设：…`）、涉及的表与字段 |
| `errors.md` | 用户反馈 SQL 错误时记：原始 text、错误的 SQL 片段、用户指出的问题、正确写法（若用户给出） |

- 目录或文件不存在则创建。
- **写前按关键词查重**：同一模糊点已有条目时，在该条下补一次出现记录，不新增重复条目。
- 这两个文件是后续「完善知识库」的输入，因此**宁可记得啰嗦，不要漏**。
- 疑问已被知识库解答清楚的，不必记录——只记真正需要人来定的。

## 幂等

- 同一 text 重复提问，若知识库未变，产出的 SQL 与假设应一致。
- 记录只增不改写既有条目内容；重复出现只累加出现记录。
