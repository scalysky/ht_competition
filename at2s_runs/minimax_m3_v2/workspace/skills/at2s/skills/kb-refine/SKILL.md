# kb-refine — 验证并晋升知识

用于消化 `.knowledge/troubleshooting/` 中的疑问和错误。troubleshooting 是候选区，不等于稳定知识；只有通过晋升门禁的通用事实才能写入 architecture 或 conventions。

## 输入与触发

- `questions.md`：未解决口径、别名和假设。
- `errors.md`：用户反馈的错误及可能修正。
- 默认 `manual`。`auto` 没有常驻进程，只能在外部唤起后检查阈值。

自动模式也必须通过下述门禁，只能处理已有用户确认或数据库验证证据的条目。

## 晋升门禁

每条候选依次回答：

1. **证据**：是否有用户确认、明确资料或可复核数据库查询？只有模型猜测则保留候选。
2. **可泛化**：是否描述表结构、码值、业务口径、别名或跨题可复用的 SQL 规则？单题常量、题号、偶然结果和整段 SQL 不晋升。
3. **无泄漏**：是否来自标准答案、Gold、evaluation 或历史 predictions？这些只能用于诊断，不能复制到将用同一题集评测的知识库。若要提炼一般规则，还必须得到独立资料/数据库证据，并用留出题验证。
4. **无冲突**：是否与现有高可信知识冲突？冲突时停止并交给用户决定，不自动覆盖。
5. **最小修改**：能否用一条明确规则修复根因，而不是为一道题增加例外？

五项全部通过才可晋升。

## 分流

| 根因 | 写入位置 |
|---|---|
| 单表字段、粒度、日期或码值 | `architecture/<表名>.md` |
| Join、聚合放大、跨表日期 | `architecture/correlation.md` |
| 缩写、黑话、别名 | `conventions/aliases.md`；必要时在表文件留引用，不双写整段内容 |
| 跨题稳定的输出单位/精度 | `conventions/output.md` |
| 证据不足或仅单题有效 | 保留在 troubleshooting，不进入稳定知识 |

稳定知识只写结论、适用条件和来源，不写原始题号、标准答案 SQL 或模型完整推理。

## 流程

1. 列出未处理候选，合并重复根因。
2. 给每条标注证据来源、适用范围和建议状态：`晋升`、`保留候选`、`拒绝`。
3. 手动模式先向用户提交修改计划；用户确认后只改计划内文件。
4. 自动模式仅应用证据已明确且无冲突的 `晋升` 条目。
5. 在 troubleshooting 原条目追加处理状态和证据，不删除历史。
6. 更新后建议使用与学习来源隔离的留出题评测；若关键题型下降，回滚该次知识修改。

## 常见错误

| 错误 | 修正 |
|---|---|
| 用户说 SQL 错了就自动写入正确规则 | 先取得正确写法或独立证据 |
| 把模型自行假设当作已确认 | 保留候选 |
| 从 Gold 复制过滤值或 SQL | 禁止晋升，防止评测泄漏 |
| 每道错题增加一个例外 | 提炼共同根因，否则不晋升 |
| 同一别名多处维护完整副本 | conventions 为唯一来源，表文件只引用 |

## 幂等

- 已处理条目不重复晋升。
- 同一规则以规范化键更新，不重复追加。
- 未通过门禁的条目保持候选状态，不擅自下结论。
